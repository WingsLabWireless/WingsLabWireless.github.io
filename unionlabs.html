Platform capabilities

UnionLabs aims to make geographically distributed testbeds easier to discover, operate, and share while preserving institutional ownership and control of local resources.

Global testbed federation

Connect heterogeneous wireless facilities across institutions and regions through unified resource discovery and access.

Large-scale orchestration

Coordinate cloud and edge resources, experiment sessions, and distributed deployments.

Hardware-aware experimentation

Support programmable radios, measurement instruments, computing systems, and other specialized devices using native and sidecar-based interfaces.

AI-assisted workflows

Build toward intelligent experiment setup, management, and automation using controlled tool interfaces.

Open APIs & extensibility

External researchers and institutions should be able to integrate new capabilities without modifying UnionLabs' internal services. Our proposed public extension surfaces are:

  • Federation API: discover resources, manage authorized access, and control experiment lifecycles.
  • Testbed Provider API: onboard facilities and publish available capabilities and status.
  • Device Plugin API: register device types and integrate new hardware with native or sidecar-based access.
  • AI Tool API: enable permission-aware, auditable automation.

OpenAPI specifications, SDK documentation, compatibility policies, and examples will be linked here as they are published.

Open-source containers

Containers make experiments portable and reproducible across heterogeneous testbeds. We envision two publication tracks:

UnionLabs platform images

Versioned container images and source/build instructions for approved platform components and edge services.

Community experiment images

Sample SDR, network measurement, remote instrument control, and AI experimentation environments submitted by contributors.

Community-submitted containers should undergo automated build validation, dependency and security scanning, compatibility tests, and maintainer review before inclusion in a trusted catalog. Each participating institution retains control over what may run on its own infrastructure.

Contributing to UnionLabs

We welcome future contributions from researchers, testbed operators, software developers, and industry collaborators worldwide. Proposed contributions include new device adapters, APIs, experiment containers, documentation, and AI tools.

  1. Discuss the improvementOpen an issue or proposal describing the use case, expected behavior, and affected interfaces.
  2. Develop and testWork in a feature branch or fork and include appropriate tests, examples, and documentation.
  3. Submit a pull requestFollow the repository contribution guidelines and complete automated checks.
  4. Review and integrateComponent maintainers review compatibility, quality, and security before merging.
  5. Release through stagingApproved changes are tested against a staging environment before controlled production deployment.
Repository links forthcoming. Public repositories, contribution guidelines, and issue trackers will be listed here once released.

Security & governance

Advanced cybersecurity mechanisms are integral to secure testbed access, resource management, and experiment orchestration across federated institutions.

  • Strong authentication, fine-grained authorization, and institution-controlled resource policies.
  • Isolation of experiment workloads and controlled access to physical devices.
  • Automated code and container security checks, with reviewed and versioned releases.
  • Audit trails for resource access, deployments, and automation actions.
  • Private vulnerability reporting and a maintained security response process.

These are design principles and planned open-source governance practices; individual controls and publication policies will be documented with each release.

Open-source release roadmap

We plan a phased release so that interfaces, documentation, and contribution workflows can mature before more sensitive platform components are published.

  1. Phase 1 · Public interfaces and examplesAPI specifications, SDKs, documentation, and initial example containers.
  2. Phase 2 · Testbed extensionsDevice-registration tooling, native and sidecar access components, and testbed-provider integrations.
  3. Phase 3 · Community ecosystemPlugin and container contribution workflows, AI tools, and expanded edge/orchestration releases.
  4. Phase 4 · Reusable federation deploymentReference deployment tooling and additional control-plane components after architectural and security review.
